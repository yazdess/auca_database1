# LAB 7: Primary Keys

## Concept

A **primary key** is a column (or a combination of columns) that uniquely identifies each row in a table, like a student ID identifies a student.

| Property | Meaning |
|---|---|
| Unique | No two rows can have the same value |
| Non-null | Cannot contain `NULL` |
| Immutable | Should not change once assigned |
| One per table | A table can have only one primary key |

**Why it matters:** it identifies each row, enables foreign keys (referential integrity), speeds up searches and joins (PostgreSQL automatically creates a unique B-tree index), and is essential for replication.

## Ways to create a primary key

```sql
-- 1. Column-level
CREATE TABLE students (
    student_id INTEGER PRIMARY KEY,
    name VARCHAR(100)
);

-- 2. Table-level
CREATE TABLE students (
    student_id INTEGER,
    name VARCHAR(100),
    PRIMARY KEY (student_id)
);

-- 3. Named constraint
CREATE TABLE students (
    student_id INTEGER,
    name VARCHAR(100),
    CONSTRAINT pk_students PRIMARY KEY (student_id)
);

-- 4. Add to an existing table
ALTER TABLE students ADD CONSTRAINT pk_students PRIMARY KEY (student_id);
```

## Single vs. composite primary key

A **single** key uses one column (e.g. `student_id SERIAL PRIMARY KEY`). A **composite** key combines several columns, which is useful when no single column is unique on its own.

## What I did

In the `intro` database, I created a table with a **composite primary key** of three columns:

```sql
CREATE TABLE course_enrollments (
    student_id INTEGER,
    course_id INTEGER,
    semester VARCHAR(20),
    enrollment_date DATE DEFAULT CURRENT_DATE,
    grade CHAR(2),
    PRIMARY KEY (student_id, course_id, semester)
);
```

## Auto-generated keys

PostgreSQL has several ways to generate numbers automatically (instead of MySQL's `AUTO_INCREMENT`):

| Option | Description |
|---|---|
| `SERIAL` | Auto-incrementing integer (uses an automatically created sequence) |
| `BIGSERIAL` | Same, but for very large numbers |
| `GENERATED ALWAYS AS IDENTITY` | PostgreSQL fully controls the value |
| `GENERATED BY DEFAULT AS IDENTITY` | Auto-generated, but you can insert your own value |

```sql
CREATE TABLE products (
    product_id SERIAL PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL
);
```

## Constraints enforced automatically

- **UNIQUE:** inserting a duplicate key fails with `ERROR: duplicate key value`.
- **NOT NULL:** inserting `NULL` as a key fails with `ERROR: null value in column`.
- **Index:** PostgreSQL creates a unique B-tree index on the key column(s).
